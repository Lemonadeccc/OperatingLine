# 场景 001：创建雪人

这是 OperatingLine 的第一条产品场景规范，不是固定的建模教程。文档把当前 `0.1.0` 可执行
切片与后续端到端目标分开，避免把尚未实现的聊天重规划、观察回传或 eval 导出写成现有能力。

## 用户目标

目标体验中，用户输入“创建雪人”。系统生成一个有序任务树，至少包含：场景准备、基础模型、
细节、材质、灯光、相机、渲染与结果验证。基础模型继续拆为身体下部、身体上部和头部；细节
继续拆为眼睛、鼻子、嘴、手臂和配件。

节点只有在满足以下条件时才能成为可执行叶子节点：

- 绑定一个稳定的适配器动作名和经过校验的参数。
- 描述执行前置条件和可观察的完成条件。
- 带有 Blender 内部的 UI 锚点或明确标记为“无精确锚点”。
- 声明回退策略：原生 undo、checkpoint、补偿动作或不支持。
- 执行前后各保存一份可用于验证的观察结果。

## 示例遍历顺序

```text
1 创建雪人
  1.1 准备场景
  1.2 建立基础模型
    1.2.1 创建身体下部
    1.2.2 创建身体上部
    1.2.3 创建头部
  1.3 添加面部与配件
  1.4 设置材质
  1.5 设置灯光与相机
  1.6 渲染并验证
```

自动 action 按 `dependsOn` 拓扑顺序执行；多个同时 ready 的节点再按 `order` 和 ASCII `id`
稳定排序。树的位置负责展示与引用，不替代执行依赖。

## 当前 0.1.0 垂直切片

当前仓库已经验证：

1. Blender Sidebar 能显示和折叠内置任务树，Overlay 能显示当前步骤卡片与引导线。
2. `Next` 按 DAG 顺序创建身体下部、身体上部和头部三个球体。
3. `Back`、`Start` 重置和 Extension 卸载只回收精确动作 receipt 对应的对象；复制出的用户对象
   或 Collection 即使带有相同自定义属性也会保留。
4. 默认不删除 Blender 工厂场景；清理三件套需要用户显式授权并通过保守指纹检查。
5. 以上行为在 Blender 4.5.3 LTS 与 5.1.1 的无界面集成测试中执行。

当前 Blender Extension 使用打包 fixture；Orchestrator ↔ Companion 实时计划投递、聊天节点引用、
失败观察回传和 eval 导出尚未接通。

## 目标修改与回退验收（未实现）

用户可在聊天框引用 `1.2.1` 并输入“让身体下部更粗糙”。系统应只使该节点及受影响的下游节点变为 stale，保留不相关节点；重新规划后应展示差异，再执行修改。前进和回退都必须同时更新 Blender 状态、任务节点状态和事件日志。

## 端到端目标验收（路线图）

1. UI 能显示、折叠和引用上述节点。
2. 每次叶子动作执行前说明“要做什么、在哪里做、为什么”。
3. Blender companion 能高亮目标控件或三维对象，并显示当前步骤序号。
4. 任一步骤失败后停止下游执行，展示证据并允许重试或回退。
5. 运行产物可导出为脱敏的计划、动作、观察、验证和回退记录，供 eval 使用。
